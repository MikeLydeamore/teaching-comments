# Summary: Ed.ie (teaching-comments)

A Next.js 16 + React 19 classroom engagement app where students submit typed/drawn/GIF/image responses, group questions, and poll answers during live teaching sessions.

## Key routes (src/app/):

- /join — student entry via space + session code
- /spaces/<space>/<session> — student writing/submission page
- /host — teacher home: your spaces (OAuth sign-in required)
- /host/<space>[/<session>] — teacher dashboard (live submissions, polls, timer, QR codes, charts)
- /host/<space>/settings — owner-only member sharing (invite by email, roles)
- /admin/spaces — admin page gated by the `ADMIN_EMAILS` allow-list
- /auth/login — Google/GitHub OAuth sign-in (Better Auth)

## Architecture:

- src/lib/ — storage abstraction with pluggable backends: local JSON file (dev), Neon serverless Postgres (production); also Better Auth setup (`auth.ts`, `auth-server.ts`), image upload tickets, and poll logic. Tests via Vitest.
- src/components/ — UI pieces: drawing pad, Giphy picker, QR popouts, poll overlays, results charts (pie/column/word cloud), response-time plots. All components start with `"use client"`.
- database/ — SQL schema for Neon/Postgres (`schema.sql`, `neon-app-role.sql`) plus incremental migrations. All tables are prefixed `edie_` (quick-write-tool legacy naming).
- workers/image-storage — Cloudflare-style worker for private image storage; a **separate npm project** with its own package.json, scripts (`npm run dev|deploy|test|typecheck`) and vitest config. Root commands do not cover it. See its README for hard constraints (R2 stays fully private, lifecycle rules only on `pending/`, secrets fail closed below 32 chars).
- tools/reconcile-images.mjs — maintenance CLI (`npm run reconcile-images`) auditing R2-committed images vs DB references.
- Deployed to Vercel (Analytics/Speed Insights), Tailwind CSS v4 styling.

Auth model: teachers sign in via Better Auth with Google/GitHub OAuth only (no passwords). Space access is role-based ACL in `edie_space_members` keyed by email (`owner` manages members; `editor` runs sessions). Admin = verified email in `ADMIN_EMAILS`. Students remain anonymous. Sessions are scoped per-space so identical session codes in different spaces don't share data. Auth tables live in a separate Postgres (`AUTH_DATABASE_URL`; local dev uses `docker compose up -d`); schema in `database/auth-schema.sql` is generated by `tools/generate-auth-schema.mjs`. Optional integrations: GIPHY (public key) and private image uploads (server-only secrets).

## UI design conventions

Authenticated host/admin pages must follow the existing Ed.ie page shell. Copy established patterns before inventing new ones.

Reference implementations:

- Host root: `src/app/host/page.tsx`
- Hosted space: `src/app/host/TeacherSpaceDashboard.tsx`
- Manage access: `src/app/host/[sessionCode]/settings/page.tsx`
- Session dashboard header: `src/app/host/[sessionCode]/TeacherDashboard.tsx`
- Admin: `src/app/admin/spaces/page.tsx`

### Page shell

- Use `min-h-screen bg-slate-100 px-5 py-8`.
- Use `mx-auto max-w-5xl` for normal host/admin pages.
- Use `max-w-7xl` only for dense live dashboards that need extra working room.
- Do not add gradients, coloured top strips, or one-off hero treatments.

### Breadcrumbs

Every authenticated host/admin page starts with a breadcrumb above its header. Use `mb-4 flex flex-wrap items-center gap-2 text-sm font-semibold text-slate-500`.

- Root pages use one current label: `Your spaces` or `Admin`.
- Nested pages link each parent and use the existing chevron SVG.
- The current page uses `text-slate-700`.
- Prevent overlap with the fixed account portrait on mobile when necessary.

### Header cards

- Base style: `rounded-md border border-slate-200 bg-white p-6 shadow-sm`.
- Kicker: `text-sm font-medium uppercase tracking-[0.18em] text-teal-700`.
- Title: `mt-3 text-4xl font-semibold tracking-normal text-slate-950`.
- Supporting text: `mt-2 text-sm leading-6 text-slate-600`.
- Group header actions together on the right.
- Do not put duplicate sign-out controls in headers; sign-out belongs in `AccountMenu`.

### Sections and controls

- Main sections use `mt-4 rounded-md border border-slate-200 bg-white p-5 shadow-sm`.
- Nested cards use `rounded-md`; do not introduce a different radius.
- Primary actions use the existing slate button style.
- Secondary actions use bordered white buttons with teal hover states.
- Switches use the established label-plus-slider control.
- Session access belongs in the header action group as `Accepting responses`.
- Keep only `QR popout`; do not add an inline dashboard QR panel.

### Identity and language

- Product name is always `Ed.ie`, never `Ed`.
- Use `hosted space`, not `teaching space`.
- Use OAuth profile portraits when available, with initials as fallback.
- Students/participants do not need account-management UI.

### Visual QA

- Check desktop and 390px mobile layouts.
- Check at least one dark theme.
- For substantial visual changes, capture Playwright screenshots before handoff.

## Commands & verification

- Verify changes with: `npm run lint && npm run build && npm test`
- Tests run via Vitest with zero config, scoped to `src/` only — colocated as `*.test.ts` next to source files.
- Local dev persistence lives in `.data/edie-store.json` (gitignored); deleting it resets all local sessions/submissions.
- `STORE_DELAY_MS=1500 npm run dev` injects artificial storage latency to test loading states.

## Storage backends

- New backends must implement the ~50-method `EdieStore` type in `src/lib/edie-store-model.ts`; dispatch happens in `getStore()` in `src/lib/edie-store.ts`.
- Backend selection precedence: explicit `EDIE_STORAGE_BACKEND` env (`local|neon`) → else Neon if `DATABASE_URL` set → else local JSON file.
- All domain types, validators, and size limits live centrally in `edie-store-model.ts` (submissions ≤2000 chars, drawings ≤120 strokes, polls 2–8 options, etc.). Route handlers must call these rather than re-validating.
- `SubmissionImageData` must never be sent to client components — use the `SubmissionDto` mapping instead.

## Testing patterns

- Server-only modules require `vi.mock("server-only", () => ({}))` in unit tests.
- Neon store tests use a hoisted query mock pattern-matching SQL statement prefixes (e.g. `SELECT`, `INSERT INTO edie_submissions`). Follow this idiom for any new backend tests.

## Next.js 16 API conventions

- Route handlers use the typed `RouteContext<"/api/...">` context param with async params — always `await ctx.params`.
- Teacher API routes authorize through `getAuthorizedTeacherSession(sessionCode)` returning `{ response?, session }`; pages gate access via `resolveSpaceAccess(spaceCode)` from `teacher-session-auth.ts`.
- Server-side data libs import `"server-only"` (a dependency).

## Environment variables

- Required for deployment: `BETTER_AUTH_SECRET` (≥32 chars), `BETTER_AUTH_URL`, `AUTH_DATABASE_URL`, plus at least one of Google/GitHub OAuth credentials; admins listed in `ADMIN_EMAILS` (verified emails).
- The Better Auth instance is lazy (`getAuth()` in `src/lib/auth.ts`) — never construct it at module scope or builds fail on missing secrets.
- Teacher pages/layouts set `export const dynamic = "force-dynamic"` (they read cookies).
- `DATABASE_URL` is server-only pooled Neon URL — never expose with a `NEXT_PUBLIC_` prefix.
- Image uploads fail closed unless ALL of `IMAGE_UPLOADS_ENABLED=true`, `IMAGE_WORKER_URL`, `IMAGE_WORKER_SERVICE_TOKEN`, `IMAGE_TICKET_SECRET` are set (secrets ≥32 chars).
- `NEXT_PUBLIC_GIPHY_API_KEY` is browser-exposed by design.
