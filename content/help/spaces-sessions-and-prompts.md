## The basic structure

A **hosted space** is the long-lived home for a class, module, or teaching team. It contains sessions and can be shared with other hosts.

A **session** is an activity inside a hosted space. It has its own participant access state, prompts, responses, questions, polls, and display settings.

A **prompt** is the question or instruction currently shown to participants. One session can contain several prompts over time.

```text
Hosted space
├── Session: week-1
│   ├── Prompt 1
│   ├── Prompt 2
│   └── Responses, questions, and polls
└── Session: week-2
```

## Choose between a new prompt and a new session

Change the prompt when the activity is continuing with the same group and you want to keep the work together. Ed.ie records prompt history, so you can later filter responses to an earlier prompt.

Create a new session when the activity or resulting dataset should remain separate—for example, a different class meeting, cohort, or assessment activity.

## Understand the two codes

Participants identify the hosted space first and the session second. The same session code can therefore be used in different hosted spaces without mixing their data.

The QR code contains the correct participant link for both codes. If someone lands in the wrong activity, close the old QR popout and open **QR popout** from the intended session dashboard.

## Understand what participants need

Participants do not create accounts. They can join with the codes or QR link and may leave the name field blank to participate as Anonymous.

Hosts sign in because hosted-space access, session controls, and saved activity belong to a teaching account.
